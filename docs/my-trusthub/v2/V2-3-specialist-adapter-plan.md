## Per-hub mapping

### Wave A — Move

- **Current profile identity:** `Company.slug` is the local Save key and `/companies/{slug}` route. `Company.id` is the native `public.companies` identifier. `lib/customer-integration/handoff.ts` emits that ID as `native_profile_id` with existing class `mover`; the claim gate accepts UUID or compatible `usdot-*` IDs. Do not substitute a slug for an existing ID binding. Proposed binding-backed tuple is `{hub:'move', nativeId: company.id, profileClass:'mover'}` after exact resolver acceptance; the selected local item retains `companySlug`. S3 must reconcile this with the parent document's slug wording. Capabilities/consumer roles are not new profile classes.
- **Publication:** `app/(move)/companies/[slug]/page.tsx` resolves through `getCompanyBySlugAsync`, accepts only `!isAnonymousCompanyNotFound`, and redirects known aliases to the canonical slug. `lib/provider/publication.ts` excludes INGESTED/CLASSIFIED/REVIEW_REQUIRED/INACTIVE. PUBLISHABLE/noindex and legacy public rows are not automatically unsaveable. Do not use SEO indexability, USDOT-only business claim eligibility, Watch availability or Florida as the basic Save gate. State-only/NJ profiles without a reviewed binding stay local rather than being falsely unsupported.
- **Guest storage:** `lib/save-my-move/local-shortlist.ts`, key `mth-local-saved-movers`, array `{companySlug,companyName,notes?,savedAt}`. Slug deduplication preserves existing notes/time. No native ID or transactional revision exists in this blob.
- **Legacy account:** server `actions/save-my-move.ts`, `saved_movers`, verified `user_id` + `company_slug` conflict key. The local key is also a cloud-failure device copy. A Move account row is NOT parent My TrustHub acknowledgment.
- **Control/producer:** `components/company/company-research-hero.tsx` → `components/save-my-move/save-mover-button.tsx` → `lib/save-my-move/save-mover-runtime.ts` / `save-mover-intent.ts`; deferred provider remains nonessential for first Save.
- **Boundary/return:** new bounded consumer BFF beside (not through) legacy auth/claim routes; exact server-resolved `/companies/{canonicalSlug}` on an approved environment origin.
- **Exclude:** saved inventories (`saved_inventories`), comparisons (`saved_comparisons`, `store/compare-store.ts`), calculators, notes, move plans and pending actions. Profile conversion must not replay the provider's unrelated pending Save/email actions.
- **Minimum proposed files:** new `lib/my-trusthub/profile-save-adapter.ts`, `profile-save-server.ts`, `selected-profile-manifest.ts`; new `app/api/my-trusthub/profile-save/{stage,receipt}/route.ts` and the agreed form-POST receive/consume route after S2; new conversion control; narrowly wire `save-mover-button.tsx` and profile identity props from `company-research-hero.tsx`. Add adapter, BFF and browser tests. These are proposed paths, not deployed endpoints.

## Shared wave execution after blockers are resolved

1. Coordinator/parent owner closes S1–S4, publishes approved typed wire fixtures and exact binding/class tables. Record safe browser → BFF → parent → DB environment pair; missing service scope/credentials fails closed. No new permissions are assumed.
2. Wave A proves one Move profile conversion end-to-end. Guest local Save remains unchanged and optional conversion remains separate. Stage selected profile-only manifest; fixed-target browser-bound form POST; parent authentication and explicit destination/selection confirmation; owner-authorized exact binding/publication Save; verify bounded per-item receipt server-side. Default retain local copies. Never trust query completion flags.
3. Wave B reuses that protocol with Insurance's distinct provider mapping and corrected allowed return route; Wave C uses exact Lender mapping and owner-scoped device cache. Their existing repair PRs remain unchanged during independent QA.
4. UI: device receipt → “Saved on this device”; conversion → “Keep this in My TrustHub”; verified matching parent receipt → “Saved to My TrustHub”; already-parent-saved → “Saved”; unresolved or failed sync → device copy retained; no durable success → “Could not save / Retry”. Legacy cloud confirmation uses the legacy workspace name, not parent copy.
5. Optional Project choice happens with parent-owned authorization; one Save may join multiple Projects. Separate Project failure from durable Save. No Project choice is mandatory. Compare/Continue remain typed hooks for later specialist-owned schemas, not bundled payloads.
6. Rollback: disable only the new adapter entry/transport via its reviewed gate, restore local-only conversion-unavailable copy, retain all local and parent records/receipts. Registration/access/notification controls are not adapter rollback controls. No destructive data rollback, automatic Watch, Alert, ranking effect or provider disclosure.
